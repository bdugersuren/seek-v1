# Даалгавар илгээх, хянах, батлах

## Дүр ба эрх
- ASSESSOR нь өөрт оноогдсон идэвхтэй контекстэд өөрийн даалгаврыг боловсруулна.
- SUPER_ADMIN нь өөрийн зохиосон биш даалгаврыг хянана, буцаана, батална, нийтэлнэ.
- Байгууллагын админ / REVIEWER_HR-д асуулт батлах шинэ эрх нэмээгүй.

## ASSESSOR
1. Үнэлгээний контекстээ сонгоод Даалгаврын сан руу орно.
2. Даалгавар нэмэх → Үргэлжлүүлэх. Нооргийг хэсэгчлэн хадгалж болно.
3. Агуулга, зөв хариулт эсвэл rubric, оноо, сэдэв болон контекстийн түвшнүүдээ бүрэн тохируулна.
4. Гуравдугаар алхамд тайлбар бичиж Батлуулах хүсэлт илгээх дарна.
5. Хяналтад орсон хувилбарыг шууд өөрчлөхгүй. Хэрэгтэй бол дэлгэрэнгүй хуудаснаас Хүсэлтээ татах дарна.
6. Засварт буцаасан үед шийдвэрийн тайлбарыг уншаад засаж, дахин илгээнэ.
7. Нийтлэгдсэн даалгаврыг засах бол Шинэ хувилбар боловсруулах дарна. Хуучин нийтлэгдсэн хувилбар, түүнийг ашиглаж буй quiz өөрчлөгдөхгүй; шинэ хувилбарын ангиллыг шалгаж тохируулна.

## SUPER_ADMIN
1. Зүүн цэсний Даалгавар батлах хяналт (/admin/questions) руу орно.
2. Хяналтад төлөвийн жагсаалтаас даалгавраа сонгоно. Контекст, зохиогч, огноо, код/гарчгаар шүүж болно.
3. Агуулга, зөв хариулт, оноо, ангиллыг шалгана. Өмнөх хувилбар байвал харьцуулж үзнэ.
4. Засварт буцаах / Татгалзах үед тайлбар заавал бичнэ. Хангалттай бол Батлах дарна.
5. Баталсны дараа Нийтлэх дарж үнэлгээнд ашиглахад бэлэн болгоно. Энэ нь PRIVATE/TENANT/PUBLIC харагдах хүрээг өөрчлөхгүй.
6. Шинэ quiz-д ашиглахаа болих үед Ашиглалтаас гаргах дарна. Өмнөх quiz revision-ийн холбоосууд хадгалагдана.

## Мэдэгдэл ба алдаа
- ASSESSOR-ийн даалгаврын сан дахь Шийдвэрийн мэдэгдэл, дэлгэрэнгүй дэх түүхээс тайлбар, төлөв, үйлдсэн хэрэглэгч, огноог харна.
- 409: өөр хэрэглэгч/цонх хувилбарыг шинэчилсэн. Хуудсаа шинэчлээд дахин шалгана.
- 403: уг төлөвт үйлдэл хийх эсвэл контекстэд хандах эрхгүй.
- 400: агуулга, хариулт, rubric, оноо эсвэл ангиллын тохиргоог засна.
- SMTP илгээхийг энэ эхний хувилбарт нэмээгүй; апп доторх шийдвэрийн мэдэгдэл, түүх ажиллана.

## Техникийн гэрээ
POST /api/v1/assessment/questions/:id/workflow:
```
{ action, questionVersionId, expectedRevision, requestId, comment? }
```
Төлөв, actorUserId, actorRole-ийг сервер тогтооно. Ижил requestId-г давтаж илгээхэд өмнөх үйл явдлыг буцаана. Буцаах/татгалзахад comment заавал. Хяналт, хадгалалт нэг question row lock-оор зохицуулагдана. UI нь хадгалсан revision-ээ submit-д ашиглана.

Пагинацтай хяналтын API: GET /api/v1/assessment/questions?review=true&status=IN_REVIEW&page=1; SUPER_ADMIN-д зориулагдсан. Өмнөх filterгүй жагсаалтын хариу array хэвээр.

Хувилбарын classificationSnapshot болон validatedQuestionVersionId нь нийтлэгдсэн ангиллыг хадгална. QuizService нь нийтлэгдсэн хувилбарыг түгжиж дахин уншаад questionVersionId-г revision-д тогтооно; draft fallback байхгүй.
