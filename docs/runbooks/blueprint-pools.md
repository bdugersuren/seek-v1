# Blueprint: сонгосон ба дүрмийн сан

Blueprint-ийн lifecycle нь ноорог/архив; readiness нь серверээс тооцсон бэлэн/засвар шаардлагатай/шалгалт боломжгүй төлөв байна. Хоосон загвар хадгалагдаж болох ч Quiz үүсгэхэд бэлэн биш.

## Хэрэглэх урсгал

1. Контекстийн Blueprint жагсаалтаас нэр, код, сэдэвтэй ноорог үүсгэнэ.
2. Ерөнхий хэсэгт хугацаа, тэнцэх босгоо тохируулна.
3. Сонгосон санд нийтлэгдсэн асуултуудыг нэмнэ. Дүрмийн санд сэдэв/дэд сэдэв, төрөл, бодит хүндрэл, audience level-ээр шүүнэ. Нэг талбарын утгууд OR, талбарууд хоорондоо AND.
4. Сан бүрд авах тоо, нэг асуултын оноог оруулаад бэлэн эсэхийг шалгана.
5. Хадгалаад Quiz үүсгэнэ. Холбогдсон Quiz хэсгээс тогтоосон асуултуудыг харна. Ноорогт тусдаа «Ноорогийн асуултыг дахин сонгох» үйлдэл бий.

Нэг асуулт эцсийн Quiz-д давхар орохгүй. Давхцсан сангуудын сонголтыг нийтэд нь шийднэ. Seed, дүрэм, blueprint version, question/version ID нь revision snapshot-д хадгалагдана. Энгийн metadata засвар сонголтыг дахин хийхгүй. Өмнөх нийтлэгдсэн revision өөрчлөгдөхгүй.

ORDERING, FILL_BLANK, LIKERT, SJT, CASE_BUNDLE нь одоогийн runtime-д дэмжигдээгүй тул энэ урсгалаар Quiz-д сонгогдохгүй. Систем тэдгээрийг хүрэлцээнд тооцохгүй, шалтгааныг харуулна.

## Алдаа ба зэрэг засвар

- 400: талбарын утга, сангийн хүрэлцээ эсвэл override зөрчилтэй.
- 403: контекст/эзэмшигчийн эрхгүй.
- 404: нөөц олдсонгүй.
- 409: хувилбар зөрсөн, эсвэл Quiz-д ашиглагдсан хэсгийг устгах хүсэлт. Editor бичсэн өөрчлөлтийг хадгална; дахин ачаалахаас өмнө өөрчлөлтөө авч үлдэнэ. Бүтцийн устгалд Blueprint хуулбарлаж засна.
- Ашиглагдсан Blueprint-ийг устгахгүй; архивлаж болно.

Хүчингүй болсон сонгосон холбоос бүх Blueprint-ийг нуухгүй. Нууц агуулга харуулахгүйгээр засах шаардлагатайг мэдэгдэнэ.

## API ба нийцэл

`GET /assessment/blueprints?paged=true` нь `items/total/page/pageSize/facets/summary` буцаана. Хуучин хэрэглэгчийн array гэрээ хэвээр. Жагсаалтын payload хуудаслагдсан; readiness/facets-ийг эрхийн хүрээний загварууд дээр сервер тооцдог тул маш их өгөгдөлд энэ тооцооллыг тусад нь оновчлох боломж үлдэнэ.

`POST /assessment/blueprints/preview`, `POST /assessment/blueprints/:id/duplicate`, `GET /assessment/blueprints/candidates` нь одоогийн контекст, эзэмшигчийн хамгаалалттай. Actor-ийг нэвтэрсэн хэрэглэгчээс авна. Update нь `version` шаарддаг.

## Migration, нэвтрүүлэлт, буцаалт

`20260912140000_blueprint_pools` нь `quiz_template.topicId`, `quiz_section.selectionRules` нэмнэ. Хуучин загварыг зохиомол сэдвээр нөхөхгүй.

`scripts/deploy-blueprint-pools.py` зөвхөн assessment, gateway, portal-web-ийг шинэчилнэ. Скрипт exact image ID-тай verification gate шалгаж, assessment DB-г нөөцлөн, тусгаарласан PostgreSQL-д сэргээж release image-ийн migration ажиллуулсны дараа production migration/deploy гүйцэтгэнэ. `.production/evidence/blueprint-pools` дахь нөөц, env нь хувийн мэдээлэлтэй тул нийтэд хавсаргахгүй.

Өгөгдлийг буцааж устгахгүй. RULE_BASED сан үүссэн бол хуучин resolver image рүү чимээгүй буцаахыг скрипт хориглоно; нийцтэй backend-ийг хадгалж засварласан image гаргана. Шинэ сан хараахан үүсээгүй үед өмнөх гурван image болон env-ээр буцааж болно; additive баганууд үлдэнэ.

Backend build нь Prisma client-ийг `dist/generated` рүү агуулгаар нь хуулдаг. Release шалгалтад runtime DMMF дотор хоёр шинэ багана байгааг заавал баталгаажуулна: зөвхөн source typecheck хангалтгүй.
