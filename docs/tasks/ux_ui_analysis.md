# seek.mn — UX/UI Нарийвчилсан Шинжилгээний Тайлан

Энэхүү шинжилгээгээр `seek.mn` платформын UX/UI дизайн, responsive хэрэгжилт, дундын компонентуудын ашиглалт, болон ижил төстэй загваруудыг (patterns) нэгтгэн шийдвэрлэсэн байдлыг кодын баазын хэмжээнд судалж, тулгарч буй асуудлууд болон тэдгээрийг засах шаардлагатай шийдлүүдийг танилцуулж байна. 

*(Санамж: Энэхүү даалгаврын хүрээнд кодонд ямар нэгэн өөрчлөлт ороогүй болно)*

---

## 1. Ижил төстэй загваруудыг нэгтгэж шийдсэн байдал (Pattern & Component Reuse)

### 1.1. Одоогийн хэрэгжсэн байдал (Ажиглалт)
* **Дизайн Системийн Суурь (`packages/ui`)**: Системд `Button`, `Input`, `Text`, `Heading`, `Card`, `Stack`, `Grid` зэрэг олон төрлийн суурь компонентууд бий болсон нь хуудаснуудын зай (spacing), фонт, өнгө зэрэг дизайны нэгдсэн стандартыг барихад сайнаар нөлөөлж байна.
* **Layout ба Spacing**: `PageContainer`, `ContentContainer`-ийг бүх хуудсанд ашигласнаар хуудасны захын зай (padding), зэрэгцүүлэлт нэг ижил стандарттай байна.
* **Сэдэв болон хэлний нэгдсэн хэрэглээ**: `ThemeProvider` болон `useI18n` ашиглан хуудас бүрт өнгө болон орчуулгыг нэг сувгаар удирдаж байна.

### 1.2. Оновчтой бус шийдлүүд (UX/UI Сул тал)
1. **`Link` болон `Button` компонентийн нэгтгэл дутмаг**:
   - `dashboard/page.tsx`, `assessments/page.tsx`, `HomePage` (Landing page) зэрэг хуудсууд дээр Next.js-ийн `Link` ашиглахдаа товчлуурын дизайнтай харагдуулахын тулд Tailwind-ийн урт ангиудыг (`className`) хуудас бүрт давтан бичсэн байна.
   - Жишээлбэл, `/assessments/[id]` эсвэл `/dashboard` руу шилжих холбоос бүрт:
     `className="inline-flex items-center justify-center rounded-seek-md border border-border bg-surface px-seek-3 py-seek-2 text-sm font-medium text-foreground transition-colors hover:bg-surface-hover..."` гэх мэтээр бичсэн нь дизайн өөрчлөгдөх үед (жишээ нь: rounded хэмжээ эсвэл hover өнгө өөрчлөгдөх) хуудас бүрийг нэг бүрчлэн засахад хүргэх эрсдэлтэй.
2. **Медиа болон Математикийн рендеринг inline байгаа нь**:
   - `MathText` (математикийн томъёог хувааж, sup/frac хэлбэрээр хэвлэдэг функцууд) болон `MediaAttachments` (зураг, видео, аудио, файл харуулдаг хэсэг) нь одоогоор зөвхөн `take/[attemptId]/page.tsx` файл дотор inline байдлаар бичигдсэн байна.
   - Гэвч математик томъёо болон медиа файлууд нь зөвхөн шалгалт өгөх үед бус, даалгаврын сан (Question bank), preview хийх хуудас, үр дүнгийн хуудас зэрэг олон газарт ашиглагдах тул нэгтгэх шаардлагатай.
3. **Шалгалтын асуултууд хэт нүсэр нэг файл дотор байна**:
   - `take/[attemptId]/page.tsx` файл нь 1200 гаруй мөр кодтой бөгөөд асуултын бүх төрлийн рендерерүүд (matching, ordering, likert, case bundle гэх мэт) inline хэлбэрээр энд бичигдсэн байна. Энэ нь асуултын бүтцийг өөрчлөх, шинэ төрөл нэмэх, эсвэл өөр хуудаснаас асуултын хэлбэрийг дуудах үед дахин ашиглах боломжгүй болгож байна.

## 2. Responsive байдал (Responsiveness & Layout Reflow)

### 2.1. Одоогийн хэрэгжсэн байдал (Ажиглалт)
* **Sidebar & AppShell**: `Sidebar` нь desktop болон tablet дээр persistent (`hidden md:flex`) байх ба mobile (768px-ээс доош) дэлгэцэнд автоматаар нуугдаж, mobile drawer цэс рүү шилждэг нь зөв responsive шийдэл юм.
* **Layout Adaptability**: `dashboard/page.tsx` болон `organisations/page.tsx` дээр `grid-cols-1 md:grid-cols-3` болон `xl:grid-cols-[minmax(0,1fr)_22rem]` ашиглаж, өгөгдлийн картуудыг дэлгэцийн хэмжээнд тохируулан зөв байрлуулж байна.
* **Шалгалтын хуудасны бүтэц**: Шалгалтын хуудасны асуултын талбар болон баруун талын navigator нь desktop дэлгэцэнд 2 баганаар харагдах боловч xl breakpoint-оос доош ороход асуулт нь дээрээ, navigator нь доороо цуварч харагдахаар зохицуулагдсан.

### 2.2. Оновчтой бус шийдлүүд (Responsive Сул тал)
1. **Матриц (Matrix) асуултын UX**:
   - `matrix` төрлийн асуултыг гар утасны дэлгэцэнд багтаахын тулд хүснэгтэд `overflow-x-auto` ашигласан. Энэ нь загвар эвдрэхээс сэргийлэх боловч touch дэлгэц дээр хэрэглэгч хүснэгтийг чирч, сонгох утгыг хайж тэмдэглэх нь маш төвөгтэй бөгөөд алдаа гаргах магадлалыг ихեսгэдэг.
2. **Mobile цэс дэх тохиргооны дутуу хэсэг**:
   - Сэдэв сонгогч (`Select` theme) нь зөвхөн desktop header дээр харагддаг (`hidden sm:block`). Харин гар утаснаас нэвтэрч ороход mobile navigation drawer дотор сэдэв солих ямар нэгэн сонголт байхгүй байна. Утастай хэрэглэгчид dark/light mode солих боломжгүй байна.

## 3. Сайжруулах Шаардлагатай Шийдлүүд (Recommendations & Gaps)

Дээрх шинжилгээнд үндэслэн UX/UI-ийг сайжруулахад чиглэсэн дараах шийдлүүдийг санал болгож байна:

### Шийдэл 1: `Button` компонентод `asChild` дэмжлэг нэмэх
Товчлуурын загвартай холбоосуудыг олноор давтан бичихгүйн тулд `@seek/ui` доторх `Button` компонентод `asChild` проп нэмнэ (жишээ нь Radix UI-ийн `@radix-ui/react-slot` эсвэл үүнтэй төстэй utility ашиглах).
* **Хэрэглэгдэх хэлбэр**:
  ```tsx
  import { Button } from "@seek/ui";
  import Link from "next/link";

  <Button asChild variant="outline" size="sm">
    <Link href="/assessments/new">Шинэ assessment</Link>
  </Button>
  ```
  Энэ нь олон газарт tailwind ангиудыг гараар давтах явдлыг бүрэн зогсоож, дизайн системийн бүрэн бүтэн байдлыг хангана.

### Шийдэл 2: Математик ба Медиа хэрэгслийг дундын сан руу шилжүүлэх
`MathText` болон `MediaAttachments` хэсгүүдийг `take` хуудаснаас салгаж, `packages/ui/src/components/` эсвэл `apps/portal-web/src/components/` дотор бие даасан shared компонент болгон үүсгэх. Энэ нь асуултын сангийн preview, үр дүнгийн хуудас зэрэг бусад хэсгүүдэд шууд ашиглагдах нөхцөлийг бүрдүүлнэ.

### Шийдэл 3: Асуултын рендерерүүдийг модульчлах
`take/[attemptId]/page.tsx`-ийн урт кодыг багасгахын тулд асуулт бүрийг (`features/candidate-attempt/components/question-types/` хавтас үүсгэн) тус тусад нь файл болгон зохион байгуулах:
* `SingleChoiceQuestion.tsx`
* `MultipleChoiceQuestion.tsx`
* `MatrixQuestion.tsx`
* `EssayQuestion.tsx`
* `NumericQuestion.tsx`
* Мөн `QuestionRenderer.tsx` нь тэдгээрийг зөвхөн dynamic import эсвэл switch-case-ээр удирддаг цэвэрхэн бүтэцтэй болох.

### Шийдэл 4: Матриц асуултыг mobile дээр adaptive болгох
Гар утасны дэлгэцийн өргөнд хүснэгтийг чирж уншихын оронд CSS/JS ашиглан дэлгэц багасах үед хүснэгтийн мөр бүрийг бие даасан Card хэлбэртэй болгож, баганын нэрсийг radio сонголт болгон reflow хийх.
* **Жишээ бүтэц (Mobile reflow)**:
  ```text
  [ Мөр 1: Даалгаврын нэр ]
  ( ) Сонголт А   ( ) Сонголт Б   ( ) Сонголт В
  
  [ Мөр 2: Даалгаврын нэр ]
  ( ) Сонголт А   ( ) Сонголт Б   ( ) Сонголт В
  ```

### Шийдэл 5: Mobile Theme Switcher
`portal-shell.tsx` дотор байрлах mobile drawer цэсэнд (`aside className="... md:hidden"`) хэл солихоос гадна сэдэв солих (Theme Select) хэсгийг нэмж байрлуулах. Ингэснээр гар утасны хэрэглэгчид dark/light mode-ийг чөлөөтэй солих боломжтой болно.
