# Realtime Gateway Contract & Decision Notes

Энэхүү баримт бичиг нь шалгалтын явцыг real-time хянах, удирдах WebSocket/SSE холболтын бүтэц болон шийдвэрүүдийг тодорхойлно.

## 1. Runtime Event Constants Mapping

Шалгалтын үед хэрэглэгдэх үндсэн event-үүдийг дараах байдлаар тодорхойлов:

- `execution:unlock` -> Администратор шалгалтыг нээх эсвэл шифрлэгдсэн асуултуудыг тайлах түлхүүр илгээхэд.
- `execution:force-submit` -> Шалгалтын хугацаа дуусах эсвэл журам зөрчсөн тул шалгалтыг шууд хураах комманд.
- `execution:warning` -> Прокторинг (proctoring) дүрэм зөрчсөн тул хэрэглэгчид анхааруулга өгөхөд.
- `execution:locked` -> Хэт олон зөрчил гаргасан эсвэл гараар шалгалтыг хаахад.
- `execution:server-time` -> Серверийн цагийг клиенттэй синхрончлох (drift-ээс сэргийлэх) зорилгоор тогтмол илгээх цагийн мэдээлэл.

## 2. Transport Decision: WebSocket vs SSE

**WebSocket (Сонгосон):**
- *Давуу тал*: Хоёр талын (bidirectional) идэвхтэй холболт үүсгэдэг тул сүлжээний хоцролт хамгийн бага байна. Мөн сүлжээний холболтыг байнгын ping/pong ашиглан шалгах боломжтой.
- *Ашиглалт*: `Socket.io` эсвэл `@nestjs/websockets` ашиглан gateway эсвэл execution сервис дээр шууд ажиллуулна.

**SSE (Server-Sent Events) (Fallback):**
- *Давуу тал*: HTTP protocol-оор явдаг тул firewall болон зарим прокси дээр илүү найдвартай ажилладаг, хэрэгжүүлэхэд хялбар.
- *Ашиглалт*: Хэрэв WebSocket холболт амжилтгүй болбол SSE холболтоор зөвхөн серверээс ирэх командуудыг (force-submit, lock) хүлээн авахад ашиглаж болно.

## 3. HTTP Fallback Endpoint Behavior

Хэрэв WebSocket болон SSE хоёулаа ажиллахгүй тохиолдолд сүлжээний асуудалтай хэрэглэгчдийг дэмжих fallback механизм:

- Клиент нь 5-10 секунд тутамд `POST /api/v1/execution/heartbeat` хүсэлтийг илгээнэ.
- `AssessmentHeartbeatResponse` дотор ирэх талбарууд:
  - `forceSubmit: boolean` -> `true` байвал клиент шалгалтыг автоматаар submit хийнэ.
  - `warning: string` -> Анхааруулга мессеж байвал UI дээр харуулна.
  - `status: AssessmentAttemptStatus` -> Хэрэв төлөв `"locked"` эсвэл `"expired"` болсон байвал шалгалтыг тэр даруй хаана.
  - `serverNow` болон `remainingSeconds` -> Шалгалтын үлдсэн хугацааг серверийн Authoritative цагаар шинэчилнэ.

Энэхүү fallback бүтэц нь сүлжээ хэчнээн тогтворгүй байсан ч шалгалт өгөх үйл явц найдвартай үргэлжлэх нөхцөлийг бүрдүүлнэ.
